🚀 3. Tantangan Rekayasa Teknis & Solusi (Metode STAR)

1. Mengatasi Bias Pilihan Jawaban LLM (Option Bias Problem)

  • Problem: Model AI memiliki kecenderungan bawaan (bias) untuk selalu menempatkan kunci jawaban benar pada opsi tertentu (misal selalu di opsi B).
  • Solution: Di backend, kami mengimplementasikan algoritma pengacakan Fisher-Yates Shuffle pada array opsi jawaban dan menyinkronkan kembali correct_answer_index sebelum dikirim ke Flutter.
  • Result: Distribusi kunci jawaban A, B, C, dan D benar-benar seimbang (25% per opsi), memberikan pengalaman kuis yang adil.

2. Mencegah Crash Parsing JSON Akibat Halusinasi LLM

  • Problem: AI terkadang menambahkan teks pembuka, penutup, atau markdown wrapper (```json ... ```) yang membuat JSON.parse gagal.
  • Solution: Dibuat algoritma Exact JSON Boundary Extractor yang memotong teks tepat dari karakter { pertama hingga } terakhir, dilengkapi regex pembersih trailing-comma dan karakter kontrol ASCII.
  • Result: 0% runtime parse crash saat memproses respons dari AI.

3. Ketahanan Jaringan & AI Rate Limit (HTTP 429)

  • Problem: Akun gratis Google Gemini rentan terhadap kuota habis (Rate Limit 429) atau gangguan jaringan sewaktu-waktu.
  • Solution: Menerapkan 3 lapis perlindungan:
    1. Multi-Model Fallback Loop: Mencoba berurutan dari model flash terbaru hingga lite.
    2. Smart Fallback Engine: Jika seluruh model Gemini gagal, server langsung menyajikan bank soal kuis edukatif lokal.
    3. Categorized Error State: Flutter membedakan tampilan offline server down (oranye) dan kuota habis (ungu).

❓ Pertanyaan Interviewer: "Apa fungsi ProviderScope dan apa jadinya jika widget ini dihilangkan?"
Jawaban: ProviderScope adalah widget penampung (container) hierarki teratas yang mengelola seluruh siklus hidup dan penyimpanan state dari provider Riverpod. Jika widget ini dihilangkan, aplikasi akan melempar runtime exception saat ada widget anak yang mencoba membaca state via ref.watch atau ref.read karena tidak ada container yang ditemukan.

B. Data Models & Immutability: lib/models/quiz_session.dart

class QuizSession {
  final List<QuizQuestion> questions;
  final int currentIndex;
  final Map<int, int> selectedAnswers; // questionIndex -> selectedOptionIndex
  final bool isCompleted;
  final String topic;

  const QuizSession({ ... });

  // Pure Getters: Menghitung skor secara dinamis
  int get correctCount {
    int count = 0;
    selectedAnswers.forEach((qIdx, ansIdx) {
      if (qIdx < questions.length && questions[qIdx].correctAnswerIndex == ansIdx) {
        count++;
      }
    });
    return count;
  }

  double get accuracy => totalQuestions == 0 ? 0.0 : (correctCount / totalQuestions) * 100;

  // Immutability CopyWith Pattern
  QuizSession copyWith({ ... }) => QuizSession( ... );
}
❓ Pertanyaan Interviewer: "Mengapa menggunakan pola immutable copyWith() dan mengapa nilai akurasi dihitung melalui getter?"
Jawaban: 1. Immutability: Menjaga integritas data dan mempermudah pelacakan state. Dengan mengembalikan objek baru lewat copyWith(), Riverpod dapat membandingkan referensi objek untuk menentukan apakah UI perlu di-render ulang secara efisien.
2. Single Source of Truth: Menghitung skor lewat getter memastikan data selalu konsisten secara matematis dengan selectedAnswers, mencegah bug desinkronisasi data nilai.

C. State Management: lib/providers/quiz_notifier.dart

class QuizNotifier extends StateNotifier<AsyncValue<QuizSession?>> {
  QuizNotifier() : super(const AsyncValue.data(null));

  Future<void> startQuiz({required String topic, required int count, ...}) async {
    state = const AsyncValue.loading(); // 👈 Transisi ke loading
    try {
      final result = await ApiService().generateQuiz( ... );
      final session = QuizSession( ... );
      state = AsyncValue.data(session);   // 👈 Transisi ke sukses membawa data
    } catch (e, stack) {
      state = AsyncValue.error(e, stack); // 👈 Transisi ke error
    }
  }

  void answerQuestion(int optionIndex) {
    final current = state.value;
    if (current == null) return;
    final updated = Map<int, int>.from(current.selectedAnswers);
    updated[current.currentIndex] = optionIndex;
    state = AsyncValue.data(current.copyWith(selectedAnswers: updated));
  }
}
❓ Pertanyaan Interviewer: "Mengapa memilih AsyncValue<T> dibanding boolean flags manual?"
Jawaban: Menggunakan boolean flags manual (bool isLoading, String? errorMessage) rawan human error (lupa mematikan loading saat error). AsyncValue menyediakan pattern matching .when() di UI yang menjamin seluruh kondisi (loading, data, error) ditangani secara lengkap dan aman dari bug UI beku.

D. Networking Layer: lib/services/api_service.dart

class ApiService {
  static final ApiService _instance = ApiService._internal();
  factory ApiService() => _instance; // 👈 Singleton Pattern

  String _getBaseUrl() {
    if (kIsWeb) return 'http://localhost:3000';
    if (Platform.isAndroid) return 'http://10.0.2.2:3000'; // 👈 Emulator Android loopback
    return 'http://localhost:3000';
  }

  String _parseDioError(DioException e) {
    if (e.type == DioExceptionType.connectionError || e.type == DioExceptionType.connectionTimeout) {
      return '[OFFLINE] Tidak ada koneksi internet / server backend belum berjalan.';
    }
    if (e.response?.statusCode == 429) {
      return '[QUOTA_EXCEEDED] Batas Kuota Gratis AI Gemini Terlampaui (Rate Limit 429).';
    }
    return '[SYSTEM_ERROR] Terjadi kesalahan sistem: ${e.message}';
  }
}
❓ Pertanyaan Interviewer: "Mengapa Android Emulator memakai 10.0.2.2 bukan localhost?"
Jawaban: Android Emulator berjalan di dalam Virtual Machine terisolasi. Jika memanggil localhost, request akan mengarah ke dalam sistem Android itu sendiri. Alamat IP 10.0.2.2 adalah rute loopback virtual khusus yang disediakan Android SDK untuk mengakses alamat 127.0.0.1 pada komputer host pengembang.

// 4. Fisher-Yates Shuffle untuk Opsi Jawaban Seimbang
function randomizeQuestionsOptions(questions) {
  return questions.map(q => {
    const correctText = q.options[q.correct_answer_index];
    const shuffled = [...q.options];
    for (let i = shuffled.length - 1; i > 0; i--) {
      const j = Math.floor(Math.random() * (i + 1));
      [shuffled[i], shuffled[j]] = [shuffled[j], shuffled[i]];
    }
    return { ...q, options: shuffled, correct_answer_index: shuffled.indexOf(correctText) };
  });
}

💡 5. Cheatsheet Tanya-Jawab Interview (Top Questions & Answers)

Q1: Apa perbedaan mendasar antara ref.watch() dan ref.read() di Riverpod?

A: ref.watch() digunakan di dalam method build() untuk mendengarkan perubahan state secara reaktif sehingga widget otomatis di-rebuild saat data berubah. Sedangkan ref.read() digunakan di dalam event callback (seperti onPressed) untuk membaca atau memanggil fungsi notifier satu kali saja tanpa berlangganan terhadap perubahan state.

Q2: Apa fungsi widget test yang Anda buat di proyek ini?

A: Widget test di test/widget_test.dart memverifikasi bahwa halaman beranda me-render teks utama 'Belajar Apa Hari Ini?' dengan membungkus aplikasi dalam ProviderScope. Ini bertindak sebagai safety net di pipeline CI GitHub Actions untuk mencegah perubahan kode yang merusak struktur tampilan ter-merge ke branch utama.

Q3: Bagaimana Anda menangani unhandled error di server Node.js?

A: Kami mendengarkan event process.on('uncaughtException') dan process.on('unhandledRejection') untuk mencatat error tanpa membuat server mati tiba-tiba, serta menambahkan error middleware khusus untuk menolak request payload berformat JSON rusak secara elegan dengan HTTP status 400.
